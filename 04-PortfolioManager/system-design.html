Portfolio Management Team — System Design

A multi-agent investment portfolio manager built with Agno, coordinated as a Team of specialist agents: portfolio proposal design, live market data, web-research gap-filling, and personal Zerodha (Kite) account access over remote MCP.

Framework Agno LLM deepseek-v4-flash (OpenAI-compatible) Serving AgentOS · FastAPI · AG-UI Sessions SQLite (agent.db) Interfaces CLI + AG-UI (SSE) MCP mcp.kite.trade (streamable-http)

01High-Level Architecture

Two entry points share the same team. The CLI (main.py) runs three agents interactively; the server (server.py) adds the zerodha_agent and exposes the team over the AG-UI protocol (SSE events at POST /portfolio/agui).

02Agents

Each agent is built by a factory in portfolio/agents/ with its own role, description, instructions and expected-output template from portfolio/prompts/.

AgentFactoryRoleResponsibilityToolsState
market_analyst_agent build_market_analyst_agent() Elite Portfolio Management Expert Assesses investor profile (risk, horizon, goals, constraints), researches macro trends, proposes strategic asset allocation with tickers, weights, risk analysis, cost breakdown and monitoring plan. ExaTools db (own session)
stock_data_agent build_stock_data_agent() Market Data Specialist Pulls current stock prices, company info/fundamentals, analyst recommendations and company news; computes allocation weights, weighted returns and FX conversions. YFinanceTools PortfolioTools —
duckduckgo_agent build_web_search_agent() Web Search Specialist Fills missing information about companies, funds and market events identified in the proposal. WebSearchTools —
zerodha_agent server only build_zerodha_agent() Zerodha Account Specialist Fetches personal Zerodha data — profile, margins, holdings, positions, MF holdings, orders, trades, GTTs, live quotes — via the Kite MCP sub-agent. Read-only by default. Kite MCP (query_kite) own session history

Team coordinator — build_team()

  • Named portfolio_management_team; shares the same OpenAIChat model and SqliteDb as members.
  • Orchestration policy (from prompts/team.py): ① get initial portfolio proposal from the market analyst → ② ensure every ticker has current price/fundamental data from the stock-data agent → ③ use web search to fill remaining gaps.
  • Context settings: add_history_to_context=True, add_datetime_to_context=True, markdown=True, show_members_responses=True, debug level 2 gated by AGNO_DEBUG.
  • Re-exports the market-analyst EXPECTED_OUTPUT template so final answers follow the full report format.

03Tools & Toolkits

Custom toolkit — PortfolioTools portfolio/tools/portfolio.py

An Agno Toolkit subclass (name="portfolio_tool") exposing deterministic finance helpers:

ToolSignatureDescriptionBackend
get_allocation_weights (portfolio_value: float, allocations: str) Dollar amount per asset-class sleeve from "stocks:60,bonds:30,cash:10"-style input; warns when weights ≠ 100%. pure Python
get_portfolio_return (weights: str, returns: str) Weighted expected return of the portfolio; validates equal-length lists and non-zero total weight. pure Python
convert_currency (amount: float, from_currency: str, to_currency: str) FX conversion with rate used; reports missing rates gracefully. httpx → Frankfurter API (ECB reference rates)

04Request Flow (happy path)

Input

CLI: rich.Prompt.ask loop → team.print_response(prompt, stream=True). Server: AG-UI client posts to /portfolio/agui; AgentOS streams SSE events back.

Market Analyst drafts the proposal

Team delegates to market_analyst_agent: investor assessment → Exa market research → asset-allocation proposal with tickers, weights, risk/cost sections per its structured EXPECTED_OUTPUT markdown template.

Stock Data enriches holdings

Team walks the proposed holdings through stock_data_agent: Yahoo Finance quotes, fundamentals, analyst recommendations, news; PortfolioTools computes sleeve dollar amounts, weighted return and currency conversion.

Gap-filling via web search

Any missing company/fund/market-event facts are resolved by duckduckgo_agent using Google-backed web search.

Zerodha context (server mode)

When asked about the user's own account, zerodha_agent routes requests through query_kite → Kite MCP (holdings, positions, margins, orders, GTTs…), handling OAuth login links if unauthenticated.

Synthesis & persistence

Team merges member responses into the final Markdown report (allocation table, risk metrics, costs, action items, sources). Conversation history persists to agent.db for both team and members.

Kite MCP lifecycle (server mode)

# server.py — FastAPI lifespan owns the connection
@asynccontextmanager
async def lifespan(_agent_os):
    await kite_provider.asetup()   # connect to mcp.kite.trade (streamable-http)
    try:
        yield
    finally:
        await kite_provider.aclose()  # close MCP session

# MCPContextProvider also reconnects lazily on first tool call if needed

05Zerodha Kite MCP Integration

🔌 Connection remote MCP

  • Endpoint: https://mcp.kite.trade/mcp, transport streamable-http, timeout 60 s.
  • MCPContextProvider(server_name="kite", model=…) wraps the server's tools in a sub-agent exposed to the zerodha agent as one gateway tool: query_kite.
  • The provider is created unconnected by build_kite_provider(); the caller wires setup/close into the app lifespan.

🔐 Authentication browser OAuth

  • No API keys. On auth errors the agent calls the login tool, which returns an authorization URL.
  • User opens the URL, signs into Zerodha in the browser, confirms in chat; agent retries the original request.
  • Guardrails: never invent/shorten the URL; never ask for passwords in chat.

🛡️ Safety policy read-only default

  • Read operations (quotes, holdings, positions, orders…) run freely.
  • Writes (place_order, modify_order, cancel_order, GTT mutations) require an explicit, confirmed instruction; the agent restates full parameters before acting.
  • Instruments must be resolved via search_instruments — never guessed tokens/segments.

📋 Reporting conventions

  • Holdings/positions rendered as Markdown tables (qty, avg price, LTP, P&L).
  • Unrealized P&L computed from average vs last traded price.
  • Flags: margin shortfalls, unusual exposure, rejected orders.

06Tech Stack

🤖 Agent framework agno

Agent, Team, AgentOS, AGUI interface, toolkits, SQLite storage.

🧠 LLM openai client

OpenAIChat pointed at DeepSeek (id="deepseek-v4-flash", base_url api.deepseek.com) with a custom role_map since the provider rejects the "developer" role.

🔗 Protocol mcp ≥1.9,<2

Model Context Protocol client for the remote Kite server (streamable-http) via MCPContextProvider.

🌐 Serving fastapi + uvicorn

AgentOS app on localhost:9001; AG-UI protocol interface streaming SSE events; compatible with CopilotKit / @ag-ui/client HttpAgent / Agent UI.

🔍 Research exa_py · duckduckgo_search

Exa API key for analyst-grade research; Google-backend web search fallback for gaps.

📈 Market data yfinance · httpx

Prices, fundamentals, analyst recs, news; custom FX via Frankfurter (ECB).

💾 Storage SqliteDb

agent.db holds sessions/chat history for the team and members; powers add_history_to_context.

🖥️ UX rich · python-dotenv

Rich terminal prompts/streaming output; .env secret loading; AGNO_DEBUG verbosity switch.

📡 Frontend AG-UI clients

npx create-agent-ui@latest, CopilotKit, or HttpAgent({url}) from @ag-ui/client pointed at /portfolio/agui.

09Running the System

⌨️ CLI mode

pip install -r requirements.txt
cp .env.example .env   # add API keys
python main.py         # type exit/quit to stop

Runs the 3-member team (no Zerodha agent) in a Rich REPL with streamed responses.

🌐 Server mode (AG-UI)

python server.py       # serves http://localhost:9001
npx create-agent-ui@latest   # point at:
                       # http://localhost:9001/portfolio/agui

Full 4-member team incl. zerodha_agent; MCP session managed in the lifespan hook. First Kite question triggers the OAuth login link flow.
